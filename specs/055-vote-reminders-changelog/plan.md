# Implementation Plan: Vote Reminders and Deployment Changelog

**Branch**: `055-vote-reminders-changelog` | **Date**: 2026-08-05 | **Spec**: [spec.md](file:///d:/Python/Discord%20Bots/ElevenBoss/specs/055-vote-reminders-changelog/spec.md)

**Input**: Feature specification from `/specs/055-vote-reminders-changelog/spec.md`

## Summary

Implement two quality-of-life automations:
1. **Top.gg Vote Reminder System**: Stores vote eligibility in a new `topgg_vote_reminders` table, executes a 30-minute APScheduler job with atomic batch claims (`claim_due_topgg_vote_reminders`), re-verifies current vote status via `check_topgg_vote()`, delivers a single gold-styled DM reminder per window, and falls back to an ephemeral store notice when DMs are disabled (`maybe_send_pending_vote_notice`).
2. **Deployment Changelog Announcement**: On startup, parses `change_log.md` using `deployment_changelog.py`, constructs a deployment key (`<version>:<commit>`), claims posting rights atomically via `claim_deployment_changelog` in `game_config`, resolves the best announcement channel, and posts a categorized update embed (`changelog_embeds.py`).

**Language/Version**: Python 3.11+ / CPython

**Storage**: PostgreSQL 15+ (Supabase) via SQL migrations (`topgg_vote_reminders` table, `game_config` table)  
**Testing**: `pytest` (unit & integration)  
**Target Platform**: Linux / Render / Hosted Python runtime  
**Project Type**: Discord Bot Application (`apps/discord_bot/`)  
**Performance Goals**: Reminder scheduler batch processing < 5s for 100 rows; Startup changelog check < 2s  
**Constraints**: Zero false-positive DMs; 100% atomic deduplication across multi-instance restarts; No `discord` imports in `packages/`  
**Scale/Scope**: ~10k user reminder capacity; 1 changelog post per deployment
